# interval-logic

`interval-logic` implements the language defined by [`LOGIC.md`](LOGIC.md).
[`CODE.md`](CODE.md) is the corresponding Python interface contract. One
trajectory-satisfaction relation supports complete-trace checking over
represented physical-time sets.

## Formula construction

```python
from interval_logic import Proposition, Signal

available = Proposition("available")
fault = Proposition("fault")
job = Signal("job")

formula = (available & ~fault).always("5]")
assignment = job.equals(3).eventually()
```

Temporal constructors take operands first and the optional parameter last.
Bare durations are half-open, a trailing `]` closes the endpoint, and
`None` means that the parameter is genuinely omitted.

```python
from interval_logic import Eventually, RelativeParameter, Until

Eventually(available, 3) == Eventually(
    available, RelativeParameter(3, include_endpoint=False)
)
Until(available, assignment, "3]")
```

## Parsing and formatting

```python
from interval_logic import format_formula, parse_formula

formula = parse_formula("always_5] (available implies not fault)")
assert str(formula) == "□_5] (available → ¬fault)"
assert format_formula(formula, unicode=False) == (
    "always_5] (available implies not fault)"
)
assert parse_formula(str(formula)) == formula
```

The parser also accepts `⊤`, `⊥`, `¬`, `∧`, `∨`, `→`, `↔`, selections,
`◇`, `□`, `U`, `W`, and `R` from `LOGIC.md`.

## Complete-trace checking

```python
import portion as P

from interval_logic import NaturalSignal, Trace, satisfying_times

trace = Trace(
    P.closed(0, 10),
    propositions={"available": P.closedopen(2, 8)},
    signals={
        "job": NaturalSignal(
            {0: P.closedopen(0, 4), 3: P.closed(4, 10)}
        )
    },
)

assert satisfying_times("eventually_2] available", trace) == P.closedopen(0, 8)
```

Use `denote(formula, trace, anchor)` for a formula's complete anchored
denotation, `satisfies(formula, trace, at)` for local truth, and
`satisfying_times(formula, trace)` to sweep the anchor. Selection masks and
conditions retain their distinct roles, but every temporal parameter uses the
same future-directed window. In particular, an absolute interval is clipped
at the current anchor for selection as well as for conditions.


## Executable contract protocol

Read [the paper companion notebook](notebooks/protocol.ipynb) for the current
paper's Sections II–III: model, quotient-based admission, unconditional offers,
bargaining, commitment and compact soundness evidence. The method stays visibly
executable in the notebook. The sibling `protocol` package supplies background
algebra, booking decisions, policy validation, independent checks and optional
Plotly presentation; it depends on `interval_logic` only in that direction.

```sh
uv sync --group notebooks
uv run --group notebooks python scripts/run_protocol_notebook.py --save
uv run --group notebooks python scripts/run_protocol_notebook.py --cwd notebooks
uv run --group notebooks python -m unittest discover -s tests
```

The runner uses a fresh kernel. After source edits, restart your interactive
kernel and Run All. Saved notebook outputs include both interactive timelines;
[the offline HTML](notebooks/interval-protocol-timelines.html) is regenerated by
the final cell from the same figure objects. The example preserves feasible
starts `{1} ∪ [3,5)`, booking `[1,2)` and price `9/2`.
See [protocol setup, package boundary and evidence](docs/PROTOCOL.md) for details.


The [charging morning scenario](notebooks/charging_morning.ipynb) applies the
unchanged method to three successive requests: full service, permitted duration
adaptation, and feasible service without agreement on price. It includes one
four-row timeline, bargaining rounds and preservation checks after each attempt.

```sh
uv run --group notebooks python scripts/run_protocol_notebook.py --notebook charging_morning --save
uv run --group notebooks python scripts/run_protocol_notebook.py --notebook charging_morning --cwd notebooks
```

Its [offline timeline](notebooks/charging_morning.html) is generated from the
same figure object. The notebook loads only definition cells from
`protocol.ipynb`; it does not copy or modify their implementations.

The [repeated-request experiment](notebooks/repeated_requests.ipynb) runs the
same method on declared synthetic days (10, 20 and 40 requests, 20 seeds each)
and on deliberate boundary cases. After every attempt it checks, by direct
interval-overlap arithmetic and trace evaluation, that earlier commitments are
retained and jointly satisfiable. It reports one outcome figure and one table of
disagreements, invariant violations and execution times. The full run takes a
few minutes; the tests use a reduced workload.

```sh
uv run --group notebooks python scripts/run_protocol_notebook.py --notebook repeated_requests --save
```
